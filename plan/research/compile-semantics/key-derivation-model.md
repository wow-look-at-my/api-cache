# The primitive set: what an engine must own

This file abstracts the three tool files into the minimal machinery a configurable engine
needs. It is **findings plus my best guess at a split**, not a decision. The planner owns
the surface shape.

---

## 1. buildcache's wrapper contract, as the primary reference

buildcache (zlib licence — code may be read and adapted) is the closest existing thing to
"a configurable compiler cache". Its per-tool rules are either C++ subclasses or **Lua
scripts implementing the same virtual-method contract**. Below is that contract verbatim in
semantics, from `doc/lua.md` and `src/wrappers/program_wrapper.hpp`, in the order
`program_wrapper_t::handle_command` calls them.

| Function | Default | Exact semantics (from the header's own documentation and the call site) |
|---|---|---|
| `can_handle_command()` | `true` (abstract in C++; Lua uses a `-- match(regex)` first-line comment plus this) | "Check if this class implements a wrapper for the given command." **Called *before* `resolve_args`, so `m_args` is not yet defined** — it must inspect the read-only `m_unresolved_args`. Dispatch is by the program's name; buildcache's gcc wrapper matches `gcc`/`g++` substrings and a clang regex, and for `cc`/`c++` it compares the invoked binary byte-for-byte against sibling `clang`/`gcc`/`clang++`/`g++` files, memoised for 30 s. |
| `resolve_args()` | copy `m_unresolved_args` → `m_args` | "Resolve special arguments so that they can be properly interpreted by later steps. The primary use case is response files." Runs first. Every later method reads `m_args`. |
| `get_capabilities()` | `{}` (everything off) | Returns a subset of `{create_target_dirs, direct_mode, force_direct_mode, hard_links}`. **Opt-in**, and `direct_mode`/`hard_links` are additionally AND-ed with the user's config; `force_direct_mode` overrides the config. |
| `get_build_files()` | `{}` | "The files that are expected to be generated by this command", as a map of **file-ID → `expected_file_t{path, required}`**. A non-required file that does not exist after the run is silently dropped from the entry. Throws to decline the command. |
| `get_program_id()` | hash of the program binary's content | "A string that uniquely identifies the program." Wrapped by `get_program_id_cached`, which keys a 300 s data-store entry on `path:size:mtime` — so the expensive identity is computed at most once per five minutes per binary. gcc's override returns `HASH_VERSION + (<compiler> --version stdout)`. |
| `get_relevant_arguments()` | **all** of `m_args` | "A list of arguments suitable for uniquely identifying the program options. **As such, things like absolute file paths and compilation defines should be excluded** (since they are resolved in the preprocess step)." |
| `get_relevant_env_vars()` | `{}` | "Environment variables that may affect program output", as a name→value map. |
| `get_hash_extra_content()` | `""` | "Extra hash data that is not covered by arguments, environment variables, or preprocessed source. Called **after** hashing relevant arguments and env vars, **before both** direct-mode and preprocessor-mode lookups." This is the escape hatch; MSVC uses it for the `/Yu` PCH content, rust for static-library content. |
| `get_input_files()` | `{}` | "The files that are used as primary input." **Only used in direct mode**, and direct mode is skipped entirely if this returns empty. |
| `preprocess_source()` | `""` | "The preprocessed source code as a string, or empty if the operation failed. **After this method has been called, `m_implicit_input_files` is expected to be defined.**" So it has two jobs: produce the text to hash, and populate the include set as a side effect. |
| `finalize_after_hit()` | nothing | "Do final work after a cache hit. An excellent place to create dynamically generated build artifacts that are not reproduced by the cache directly. An example is to create compilation unit dependency files (.d files)." |
| `run_for_miss()` | `sys::run_with_prefix(m_unresolved_args, false)` | "Run the actual command. The return value shall be a table consisting of `std_out`, `std_err` and `return_code`." MSVC overrides it to strip `/showIncludes` lines from stdout before caching. |

Globals a Lua wrapper sees: `m_args` (resolved, `m_args[1]` is the program),
`m_unresolved_args` (read-only), `m_implicit_input_files` (populated by `preprocess_source`).
A `bcache` library exposes `file_exists`, `get_dir_part`, `get_extension`, `get_file_info`,
`get_file_part`, `log_*`, `parse_json`, `run(args)`, `split_args(str)`.

### The driver's flow (`handle_command`)

```
resolve_args()
capabilities = get_capabilities()
expected_files = get_build_files()
h = hash()
h += content of every config-level "hash_extra_files"
h += get_program_id_cached()
h += get_relevant_arguments()
h += get_relevant_env_vars()
h += get_hash_extra_content()
if capabilities.direct_mode and get_input_files() is non-empty:
    dm = copy(h); dm.inject_separator()
    dm += m_args                       # the FULL argv, including -D/-I
    for f in input_files: dm += resolve_path(f); dm.inject_separator(); dm += content(f)
    if cache.lookup_direct(dm.final(), ...): finalize_after_hit(); return
h += preprocess_source()               # also sets m_implicit_input_files
key = h.final()
if cache.lookup(key, ...):
    if direct_hash: cache.add_direct(direct_hash, key, m_implicit_input_files)
    finalize_after_hit(); return
result = run_for_miss()
if result.return_code == 0 or config.cache_on_failure():
    cache.add(key, entry(file_ids, std_out, std_err, return_code), expected_files)
    if direct_hash: cache.add_direct(direct_hash, key, m_implicit_input_files)
return result.return_code
```

### Where this contract is too coarse or missing something

The user's reaction — that this surface is hard to reason about — is well founded, and the
specific gaps are concrete. Measured against what `c-cxx-gcc-clang.md`, `msvc.md` and
`rustc.md` say correctness needs:

1. **Every hook hand-parses argv from scratch.** `get_build_files`, `get_relevant_arguments`,
   `get_input_files`, `preprocess_source` and `maybe_generate_dependency_file` each walk
   `m_args` with their own ad-hoc loop and their own `skip_next_arg` state machine. In
   buildcache's own gcc wrapper those five loops disagree: `get_build_files` does not know
   about `-MF`, `maybe_generate_dependency_file` throws on `-MQ`, and
   `is_arg_plus_file_name` lists only `{-I, -MF, -MT, -MQ, -o}` — so `-include foo.h`,
   `-isystem dir` and `-D FOO` (separated form) all have their **values misread as source
   files**. That is not a hypothetical: `gcc -isystem /opt/inc -c a.c -o a.o` would be
   classified as two input files. One shared argv model would make the bug impossible.
2. **No verdict vocabulary.** Declining is `throw std::runtime_error(...)` with an ad-hoc
   string, caught and logged at the top. There is no closed reason set, so nothing can be
   counted, no user can be told *why* their build does not cache, and no two wrappers
   report the same condition the same way. ccache's 40-odd named statistics (§4 below) are
   the thing to copy.
3. **No role for "a path whose content is an input".** `get_hash_extra_content()` is the
   only place to say it, and it is a single opaque string computed however the wrapper
   likes. MSVC's PCH and rust's static libraries both go through it, differently. There is
   no declarative way to say "`-fprofile-use=<p>` means hash `<p>`'s content", which is why
   buildcache's gcc wrapper does not handle `-fprofile-use` at all.
4. **No environment hashing for gcc.** `gcc_wrapper_t` never overrides
   `get_relevant_env_vars()`, so it inherits the empty default. **`CPATH`, `C_INCLUDE_PATH`,
   `CPLUS_INCLUDE_PATH`, `SOURCE_DATE_EPOCH`, `LANG`/`LC_*`, `COMPILER_PATH` and
   `GCC_EXEC_PREFIX` are all absent from the key.** Every one of those changes the output;
   ccache hashes all of them. This is a live correctness bug, and it exists precisely
   because "which env vars matter" is a per-hook imperative decision rather than a stated
   table.
5. **No temporal-macro handling.** The header carries the TODO in the direct-mode loop:
   `// TODO(m): Check file for disqualifying content (e.g. __TIME__ in C/C++ files).`
   So a source using `__TIME__` gets a direct-mode hit with a stale time baked in.
6. **`preprocess_source()` does two unrelated jobs** — produce the hashable text *and*
   populate `m_implicit_input_files` — coupled only by a comment. A tool that reports its
   include set without a preprocessing step (rustc's `--emit=dep-info`, MSVC's
   `/sourceDependencies`) has to fake one; buildcache's rust wrapper's `preprocess_source`
   returns a **concatenation of file digests joined by control characters**, which is not
   preprocessed source in any sense.
7. **`get_build_files()` cannot express a derived sibling.** It can, imperatively (the gcc
   wrapper computes `.gcno` by changing the object's extension), but there is no way to say
   it declaratively, so `.dwo`, `.su`, `.ci`, `.dia` and the rustc `.rmeta` set are each a
   bespoke branch. buildcache handles `.gcno` and misses `-gsplit-dwarf` entirely.
8. **Only one dep-file model, and it regenerates rather than caches.**
   `finalize_after_hit` → `maybe_generate_dependency_file` writes a `.d` from
   `m_implicit_input_files`, **without escaping spaces**, with the target taken from `-o`
   (so `-MT` is honoured but `-MQ` throws), and from an include list that its own TODO
   admits omits implicit includes like `/usr/include/stdc-predef.h` — which gcc's real
   `-MD` output *does* list (measured). A cached-and-rewritten dep file, as ccache does, is
   both simpler and more faithful.
9. **No manifest with multiple candidates.** `cache.add_direct(direct_hash, key, files)` is
   one direct-hash → one result. ccache keeps up to 100 candidate include-sets per key
   (`c-cxx-gcc-clang.md` §3) precisely because one command line legitimately reads different
   include sets in different environments. Without that, buildcache's direct mode thrashes
   rather than validating.
10. **No stderr normalization.** Nothing forces colour on for the child or strips it on
    replay, so a buildcache hit replays colourless diagnostics to a terminal user.
11. **Coarse sloppiness.** One three-level `accuracy` enum gates two decisions, versus
    ccache's fourteen individually named, individually loggable relaxations.
12. **`can_handle_command()` runs before `resolve_args()`**, so a wrapper that needs to see
    inside a response file to decide cannot. It is a small thing, but it is the kind of
    ordering constraint that a data-driven dispatch would not have.

**What buildcache gets right and should be kept**, regardless of surface shape:
the two-key structure with an injected separator between direct and preprocessor modes;
memoising the program identity by `path:size:mtime` with a short TTL; a per-rule
`HASH_VERSION`; `expected_file_t{path, required}` so an optional output can be absent;
`terminate_on_miss` as a debugging mode; capabilities that are AND-ed with user config;
and the discipline of refusing an argument it does not fully understand (in the rust
wrapper, though not the gcc one).

## 2. The primitive inventory

Grouped by stage. Each entry says what it does and cites where the need was established.

### 2.1 Argv model

| Primitive | What it does |
|---|---|
| `expand-response-files` | `@file`, recursively for GNU, **one level** for MSVC, BOM-aware UTF-16 decode for MSVC, shell-like quoting, unopenable file left verbatim. Must run before anything else sees argv. |
| `parse-argv(syntax)` | A named per-family parser: `gnu` (`-o x` / `-ox` / `--opt=x` / `--opt x`), `msvc` (`/Fox` / `/Fo:x` / `-Fox`, `--` before the source), `rustc` (long `=`-or-separated, short concat-or-separated, `KIND=PATH`, `KIND[:MODS]=NAME[:RENAME]`). Produces `(flag, value, spelling)` triples. |
| `forward-split` | `-Wp,a,b` / `-Xpreprocessor a` / `-Xclang a` / `-Xcompiler a`: split the payload and re-dispatch through the same table, so a forwarded `-MD` is seen as `-MD`. |
| `classify(arg) -> role` | Look the parsed flag up and attach a role. Roles listed in `c-cxx-gcc-clang.md` §10.2. |
| `positional-language(ext, -x state)` | Extension → language, with `-x` overriding and `-x none` clearing. Feeds the `unsupported_source_language` verdict and the "already preprocessed → skip the preprocess step" decision. |

### 2.2 Verdict

| Primitive | What it does |
|---|---|
| `verdict(reason)` | Decline, with a code from the **closed vocabulary** (§4). Never a free-form string. |
| `mode flags` | `compiling`, `linking`, `preprocessing-only`, `syntax-only`, `generating-deps`, `generating-includes`, `debug-info`, `split-dwarf`, `coverage`, `pch-create`, `pch-use`, `lto`, `profile-generate`, `profile-use`, `modules`. The verdict logic is a small predicate over these plus the input/output counts. |
| `gate(sloppiness-name)` | Turn a verdict into a permission when a named relaxation is enabled, and **log which one fired**. |

### 2.3 Hashing

| Primitive | What it does |
|---|---|
| `hash-begin(format-version)` | Start a hash pre-salted with the engine version **and** the rule's own version. |
| `hash-delimiter(tag)` | Frame and tag. Mandatory between every logical item — see `hashing-and-normalization.md` §1. |
| `hash-bytes` / `hash-string` | |
| `hash-file-content(path)` | With a stat-keyed memo (an inode cache). |
| `hash-file-stat(path)` | size + mtime (+ ctime), for the `file_stat_matches` fast path. |
| `hash-archive-content(path)` | `.a`/`.lib` hashing that ignores embedded timestamps (sccache's `hash_all_archives`). |
| `hash-normalized-path(path)` | Apply prefix maps (reverse order) and base-dir relativisation, then hash the result. |
| `hash-tool-identity(policy)` | `mtime+size` \| `content` \| `run <cmd> and hash stdout` \| `literal string`. Memoised by `path:size:mtime` with a short TTL. |
| `hash-tool-expansion(query-args, extract)` | Run the tool to find what a flag expanded to and hash *that* — `-### -E -` for `-march=native`, with a per-compiler line extractor. |
| `hash-env(allowlist)` | Named variables only; `unset` must be distinguishable from empty (rustc's `env-dep` without `=`). |
| `fork-hash(tag)` | Copy a partial hash and inject a separator, so two derived keys (direct vs preprocessed) can never collide. |

### 2.4 Input discovery

| Primitive | What it does |
|---|---|
| `run-preprocess(argv-transform)` | Build the preprocessing argv from the compile argv by dropping `-c`/`-o`/`-M*`, adding `-E` (± `-P`), and adding the include-report flag. Capture stdout (the text) and stderr (diagnostics **and**, for `-H`, the include list). A non-zero exit → `preprocessor_error`. |
| `depfile-parse` | Makefile tokenisation: `target: prereq …`, ` \`+newline continuations, escapes (`\ `, `$$`, `\#`), Windows drive-letter disambiguation. |
| `depfile-escape` | The inverse, for a dep file the engine writes. |
| `depfile-rewrite-target(new)` | Replace everything up to the first `": "`. Used on a hit when `-MT`/`-MQ` differ from what was stored. |
| `depfile-relativise(base-dir)` | Rewrite absolute prerequisites; **leave the target alone**. Used on a miss before storing. |
| `showincludes-parse(prefix)` | Split lines on the localized prefix, preserving the indentation depth. |
| `showincludes-prefix-detect` | The runtime probe in `msvc.md` §4 — no locale table. |
| `showincludes-strip` / `showincludes-emit` | Remove the lines from cached stdout; regenerate them (with depth) on a hit. |
| `linemarker-scan` | Build the include set from `-E` output's `# N "path"` markers. |
| `json-dep-parse` | `/sourceDependencies` and any other structured dep output. |
| `temporal-macro-scan(file)` | Word-boundary-aware search for `__DATE__`, `__TIME__`, `__TIMESTAMP__`, `#embed`, `.incbin`, returning a bitset; drives direct-mode disabling and digest adjustment. |

### 2.5 Manifest

| Primitive | What it does |
|---|---|
| `manifest-lookup(direct-key)` | Fetch the candidate list. |
| `manifest-validate(candidate)` | For each `(path, digest, size, mtime, ctime)`: stat → size check → optional stat-match fast path → content hash. First fully-matching candidate wins. |
| `manifest-add(direct-key, result-key, files)` | Append a candidate, bounded (ccache: 100 results / 10 000 file infos, then reset). |
| `manifest-intern` | Share path strings and file-info records across candidates — the reason ccache's manifest is three parallel vectors with indexes rather than a list of maps. |

### 2.6 Outputs

| Primitive | What it does |
|---|---|
| `output-from-argv(role)` | The `-o` / `/Fo` value, or a derivation from the source basename plus a mode-dependent extension. |
| `derive-sibling(base, ext)` | `.dwo`, `.gcno`, `.su`, `.ci`, `.d`, `.rmeta`. Suppressed when the base is `/dev/null`. |
| `output-from-tool-query` | rustc's `--print file-names`. |
| `capture(path, required)` | Store; a missing non-required output is dropped, a missing required one is `compiler_produced_no_output`, a zero-byte one is `compiler_produced_empty_output`. |
| `capture-streams` | stdout, stderr, exit code — **always**, for every rule, including rules with no file outputs at all (clang-tidy). |
| `restore(path, mode)` | temp-in-destination-directory + rename; caller's umask; preserve the executable bit. |
| `restore-streams` | Replay stdout and stderr **verbatim**, then exit with the stored code. |
| `diagnostics-color-force` / `diagnostics-color-strip` | Force colour on for the child; strip on replay when the user's stderr is not a TTY or `…-color=never` was requested. |
| `scratch-dir` | A per-invocation temp directory, removed on exit and on signal. |

### 2.7 Process

| Primitive | What it does |
|---|---|
| `resolve-tool` | basename-only when masquerading, skip canonicalised argv[0], reject the wrapper binary, keep `virtual` and `real` paths. |
| `recursion-guard` | Set a disable env var for the descendant subtree. |
| `run(argv, env-delta)` | With `unset-around-child` support (`VS_UNICODE_OUTPUT`, buildcache's rust list). |
| `signal-shield` | INT/TERM/HUP/QUIT; forward TERM to the child; unlink temps signal-safely; `waitpid`; re-raise. |
| `input-freshness-check` | The "too new" rule (`hashing-and-normalization.md` §5.1), applied after the run to the source and every recorded include. |

## 3. Data flow

```
                       argv, env, cwd
                             |
                 [expand-response-files]           <- recursive (GNU) / 1 level (MSVC)
                             |
                     [parse-argv(syntax)]
                             |
                 [classify each -> role]  --+--> mode flags
                             |              |
                             |              +--> verdict?  --yes-->  BYPASS(reason)
                             |                                        exec the real tool
                             v
     +----------------- common hash -------------------+
     | version | tool identity | tool name | env allow |
     | filtered argv | native-arg expansion | cwd?     |
     +---------------------+---------------------------+
                           |
              +------------+------------+
              |                         |
       [fork-hash "direct"]      (fall through)
              |                         |
   + full argv (incl -D/-I)             |
   + cpp env (CPATH, INCLUDE...)        |
   + source path + source content       |
              |                         |
        direct key                      |
              |                         |
       [manifest-lookup]                |
              |                         |
      candidates: [ {files:[(path,digest,size,mtime,ctime)], result_key}, ... ]
              |                         |
     [manifest-validate] --first match--+--> result key ------+
              |                                               |
           all miss                                           |
              |                                               |
              v                                               |
     [run-preprocess]  --nonzero--> BYPASS(preprocessor_error) |
              |                                               |
    text (+ -P?)  +  cpp stderr  +  include set               |
              |                                               |
        + hash text, + hash cpp stderr                        |
              |                                               |
        preprocessed key ------------------------------------>+
                                                              |
                                                              v
                                                    [result lookup]
                                                       /          \
                                                     HIT          MISS
                                                      |             |
                                           [restore outputs]   [run tool]
                                           [restore streams]        |
                                           [depfile-rewrite-target] [input-freshness-check]
                                           [showincludes-emit]      |  --moved--> modified_input_file
                                                 exit code          |
                                                                [depfile-relativise]
                                                                [showincludes-strip]
                                                                [capture outputs+streams]
                                                                     |
                                                          exit != 0 ? store nothing
                                                                     |
                                                                [store result]
                                                                [manifest-add(direct key,
                                                                              result key,
                                                                              include set)]
                                                                     |
                                                                  exit code
```

Depend mode is the same picture with the `[run-preprocess]` box deleted: the tool runs
first, and the result key is derived from the dep output it produced.

## 4. The closed reason vocabulary

ccache's complete uncacheable/error set (`src/ccache/core/statistics.cpp`), which is the
list to start from because it is the accumulated result of twenty years of field reports.
`FLAG_UNCACHEABLE` = "this invocation cannot be cached"; `FLAG_ERROR` = "something went
wrong". The rest are counters, not verdicts.

**Uncacheable (the verdict vocabulary):**

| code | Message |
|---|---|
| `autoconf_test` | Autoconf compile/link (an input path containing `conftest.`) |
| `bad_compiler_arguments` | Malformed argument: a missing value, or an unreadable file named by one |
| `called_for_link` | No `-c`/`-S`/`-fsyntax-only`/`-dc`/`-analyze` |
| `called_for_preprocessing` | `-E`, `-M`, `-MM`, `/EP` |
| `compile_failed` | The compile failed; nothing stored |
| `compiler_produced_no_output` | An expected output file was missing afterwards |
| `compiler_produced_empty_output` | An expected output file was zero bytes |
| `compiler_produced_stdout` | *(obsolete — stdout is cached now)* |
| `could_not_use_modules` | `-fmodules` preconditions unmet |
| `could_not_use_precompiled_header` | PCH preconditions unmet |
| `disabled` | Disabled by a comment in the source |
| `multiple_source_files` | More than one source with `-c` |
| `no_input_file` | No input |
| `output_to_stdout` | `-o -` |
| `preprocessor_error` | The `-E` run failed |
| `recache` | A forced recache overwrote an entry |
| `unsupported_code_directive` | `.incbin` found |
| `unsupported_compiler_option` | A TOO_HARD option |
| `unsupported_environment_variable` | `DEPENDENCIES_OUTPUT`, `SUNPRO_DEPENDENCIES`, MSVC `CL`/`_CL_` |
| `unsupported_source_encoding` | Non-UTF-8 source under MSVC |
| `unsupported_source_language` | Unknown `-x` or unknown extension |

**Errors (a bug somewhere, not an ordinary decline):**

| code | Message |
|---|---|
| `bad_input_file` | Could not read or parse an input file |
| `bad_output_file` | Could not write the `-o` path, or its directory does not exist, or it is not a regular file |
| `compiler_check_failed` | The configured compiler-check command failed |
| `could_not_find_compiler` | |
| `error_hashing_extra_file` | A configured extra-file-to-hash was unreadable |
| `internal_error` | |
| `missing_cache_file` | An entry vanished between lookup and read (a concurrent cleanup) |
| `modified_input_file` | An input was modified during the compilation (the "too new" rule) |

**Additions the three tool files show are needed and ccache lacks:**

| proposed code | When |
|---|---|
| `unsupported_output_kind` | MSVC `/Zi`/`/ZI` — a shared, accumulating artifact. ccache reports `unsupported_compiler_option`, which does not tell the user the remedy is `/Z7`. |
| `unresolvable_input` | rustc `-l static=z` with no matching archive on the `-L` path. |
| `incremental_state` | rustc `-C incremental` — an opaque artifact tree. |
| `unsupported_dep_output_combination` | `-Wp,-MD` together with `-MF` (gcc and clang disagree). |
| `ambiguous_include_set` | *(new)* the gcc `#pragma once` content-dedup case, if ever detected. |

Every verdict must carry the **triggering argument or variable** alongside the code, or the
user cannot act on it.

## 5. Engine primitive vs. expressible in config — my best guess

**This is a recommendation, not a decision.** The one firm input is that a surface where
each rule hand-parses argv is too hard to reason about. Two shapes could satisfy that; both
are noted.

| Concern | My guess | Why | The alternative |
|---|---|---|---|
| Response-file expansion | **engine** | Recursion depth, MSVC's one-level rule, UTF-16 BOMs, quoting. Three tools, three dialects, zero per-project variation. | A rule names a dialect; there is nothing else to say. |
| Argument syntax (`-ox` vs `-o x` vs `/Fo:x`) | **engine**, selected by a named dialect | This is where buildcache's five disagreeing loops come from. | A rule could supply a regex per flag; that reintroduces the bug. |
| Which flag means what | **config** | This is genuinely per-tool knowledge, it changes with every compiler release, and it is a large table. The per-tool tables in the three tool files are exactly this content. | Hard-coding it makes adding a tool a code change, which is the whole point of the project. |
| Forwarding (`-Wp,`, `-Xclang`) | **engine** | It is a re-dispatch through the same table; a rule only marks which flags forward. | — |
| Verdict reasons | **engine** (closed set) | A free-form string cannot be counted or acted on. | Config supplies the *condition*, engine supplies the *code*. |
| Verdict conditions | **config** | "more than one source is fatal when compiling, and means link otherwise" is tool knowledge. | A fixed predicate would not fit rustc (which has entirely different requirements). |
| `.d` parse / escape / rewrite | **engine** | The escaping rules diverge per compiler and are subtly wrong in every hand-rolled version I read, including buildcache's (no space escaping) and sccache's clang-cl path (skips any path with a space). | — |
| `/showIncludes` parse + prefix detection | **engine** | The runtime prefix probe is 40 lines of careful logic; no rule author should write it twice. | — |
| Derived sibling outputs | **engine**, driven by a config-stated `derived-output:<ext>` | The derivation is "swap the extension"; which extension, for which flag, is tool knowledge. | — |
| Include-set → manifest | **engine** | The multi-candidate structure, interning, validation order and bounds are pure mechanism. | — |
| Prefix mapping / base-dir | **engine** | Reverse-order application, cwd interaction with `hash_dir`, and the interaction with debug info are all subtle and uniform. | Config states *which flags* are prefix maps. |
| stderr colour force/strip | **engine** | Needs to know the user's TTY state, which a rule cannot see. Config states the per-compiler flag spelling (`-fdiagnostics-color` vs `-fcolor-diagnostics`). | — |
| Temporal-macro scan | **engine** | One scanner, word-boundary aware, shared by every C-like rule. Config states whether the rule uses it. | — |
| Tool identity policy | **engine** mechanism, **config** choice | Four policies (`mtime`/`content`/`command`/`string`) and a memo; the rule picks one and supplies the command. | — |
| Tool-expansion query (`-### -E -`) | **engine** mechanism, **config** query | The extractor differs per compiler (`/cc1 -E` vs `"-cc1"`, plus clang's arch-only filter), so the *query and extraction* belong in config. | — |
| Env allowlist | **config** | Purely per-tool knowledge, and the place buildcache's gcc wrapper has a real bug by omission. | — |
| Env `unset-around-child` | **config** list, **engine** mechanism | `VS_UNICODE_OUTPUT`, buildcache's rust list. | — |
| The preprocessing argv transform | **config** with engine help | "drop `-c`/`-o`/`-M*`, add `-E`, add `-P` unless debug/coverage, add `-H`" is tool knowledge; "run it and capture three streams" is mechanism. | — |
| Sloppiness knobs | **engine** (a named registry), **config** (which apply where) | Named, loggable, off by default — ccache's pattern. | A single `accuracy` level is buildcache's, and is demonstrably too coarse. |
| Manifest bounds, cache layout, eviction | **engine** | Nothing per-tool. | — |
| Atomic restore, umask, hard-link policy | **engine** | Nothing per-tool except whether hard links are *safe* for that tool's outputs, which is one boolean. | — |
| Signals, recursion guard, tool resolution | **engine** | Nothing per-tool. | — |
| An escape hatch for the genuinely weird | **config: a template or a small script** | nvcc's `--dryrun` decomposition, clang-CUDA's per-arch chunk splitting, `/Yu`'s PCH-path resolution order. Some things are not a table. | Hard-coding them means a new compiler needs a new release. |

**The shape I would suggest the planner consider**, stated as a suggestion: the flag
knowledge is large, flat and mechanical, which argues for a table; but three things in the
tables above are *not* flat — `/FI`'s resolve-against-the-source-directory second pass,
`/Yu`'s three-step PCH path resolution, and rustc's `-l static=` search along `-L` — and
each needs an expression, not a cell. A table of meanings plus a template escape hatch
covers all three. That is one shape; a small set of hooks *over a shared argv model* (i.e.
buildcache's contract minus defect #1) is another, and would handle the irregular cases
more naturally at the cost of being harder to read at a glance.

## 6. What a rule must state, whatever the surface

Independent of shape, here is the complete list of things a correct gcc rule has to
communicate to the engine. It is a useful completeness check for any proposed surface.

1. Which programs it handles (name patterns, and a tie-break when the real path differs
   from the invoked name — `clang-cl`).
2. The argument dialect, and the response-file dialect.
3. For each flag family: how the value is spelled, and what the value means (the tables).
4. Which flag combinations are fatal, and with which reason code.
5. How to compute the primary output when it is not stated.
6. Which derived siblings exist, and under which mode flags.
7. The tool-identity policy, and any expansion query.
8. The environment allowlist, the bypass-on-presence list, and the unset-around-child list.
9. Whether a preprocessing step exists, how to build its argv, and how to read its include
   report.
10. Whether direct mode is available, and what goes into the direct key beyond the common
    part.
11. Which sloppiness knobs apply.
12. Whether the tool's outputs are safe to hard-link.
13. A format version for the rule itself.
